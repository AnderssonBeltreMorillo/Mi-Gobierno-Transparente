===============================================================================
1. RESUMEN EJECUTIVO
===============================================================================
Aplicación de auditoría de compras públicas de República Dominicana. Cruza
licitaciones de la DGCP con precios de catálogos de supermercados (Nacional,
Jumbo, La Sirena y Plaza Lama), detecta sobreprecios por renglón y los publica en un
dashboard React.

Arquitectura:
- Backend Python 3.11 con FastAPI y arquitectura Onion:
  domain -> application -> infrastructure/presentation.
- Sincronización DGCP mediante la API oficial de Datos Abiertos.
- Persistencia en Firestore (firebase-admin).
- Scraping directo de catálogos de supermercados con httpx + BeautifulSoup.
- Evaluación semántica por lotes con Google Gemini (google-genai), con fallback
  local cuando no hay API key o Gemini falla.
- Frontend React 19 + TypeScript + Vite + Tailwind CSS 4 + lucide-react.
- El frontend no accede a Firestore: consume la API FastAPI.

Fuentes de datos del dashboard:
1. Firestore, colección `licitaciones`, escrita por `dgcp_sync.py`.
2. Caso DASAC-CCC-LPA-2026-0011 codificado estáticamente en
   `presentation/routers/licitaciones.py` (dos versiones: original y enmienda).
   El endpoint `/licitaciones` fusiona ambas fuentes.

3. BACKEND: FLUJO DE dgcp_sync.py
===============================================================================
Entrypoint: `sync_licitaciones_dgcp.py` importa `main` y `evaluar_renglones`
desde `infrastructure.dgcp_sync`.

3.1. Constantes y versión del motor
- `_MOTOR_VERSION = "2026-11-escenarios-abc"`.
- `_PALABRAS_PROCESO`: alimento, despensa, comedor, raciones, aseo, limpieza,
  higiénico, higiene, supermercado, comestible, insumo alimenticio, víveres,
  canasta, productos básicos, material de limpieza, productos de aseo,
  artículos de higiene, suministros de limpieza.
- `_PALABRAS_ASEO`: cloro, detergente, desinfectante, jabón, papel higiénico,
  escoba, trapeador, limpiador, fundas, bolsas para basura.
- Host oficial de fichas: `comunidad.comprasdominicana.gob.do`.
- API oficial: `https://datosabiertos.dgcp.gob.do/api-dgcp/v1`.

3.2. `main()` — ciclo de una ejecución
1. Calcula ventana: `hoy - DGCP_LOOKBACK_DAYS` (default 120 días).
2. Lee `DGCP_MAX_PAGES` (default 20) y `DGCP_MAX_PROCESSES` (default 50 en
   código; `render.yaml` lo fuerza a 1; el README menciona 3, está desactualizado).
3. Crea `DgcpOpenDataClient`.
4. Lee filtros manuales de `DGCP_PROCESS_URLS`.
5. Descubre procesos (`_descubrir`).
6. Carga configuración y crea cliente Firestore.
7. Abre `CatalogoDirectoSupermercados` como context manager.
8. Obtiene procesos nuevos (`_procesos_nuevos`).
9. Para cada proceso nuevo:
   - Aplica filtro de rubro con `palabras_clave_permitidas` sobre
     título + descripción + objeto del proceso, en minúsculas.
   - Si no cumple, lo guarda en `licitaciones_descartadas` con motivo
     "No cumple filtro de rubro" y continúa.
   - Si cumple, llama a `_procesar_proceso`.
   - Se detiene al llegar a `max_procesos` sincronizados.
10. Si sincronizó al menos uno, termina con código 0.
11. Si no sincronizó ninguno (todos descartados), busca un pendiente de
    recálculo con `_siguiente_pendiente` y recalcula un solo documento.
12. Si no hay nada, imprime que esperará al siguiente ciclo de 2 horas.

3.3. `_descubrir()` — descubrimiento y filtros de entrada
- Si `DGCP_PROCESS_URLS` contiene códigos, busca cada código con
  `api.buscar_procesos(..., max_paginas=1, codigo=codigo)`.
- Si contiene URLs, valida que sean http/https, que el host sea
  `comunidad.comprasdominicana.gob.do` y que tengan `noticeUID`; luego filtra
  los procesos descubiertos por ese UID en su URL.
- Sin filtros manuales, recorre las páginas recientes de `/procesos`.
- Deduplica por `codigo_proceso`.
- Solo conserva procesos cuyo título/descripción/objeto contenga alguna
  `_PALABRAS_PROCESO`, comparando texto normalizado sin tildes y en casefold.

3.4. Filtro de artículos objetivo
`_articulo_objetivo(articulo)` acepta un renglón si:
- La `familia_unspsc` (solo dígitos) empieza por "50" o "47"; o
- La descripción contiene alguna `_PALABRAS_ASEO`.
Se evalúa `descripcion_usuario` + `descripcion_articulo`.

3.5. `_procesar_proceso()`
- Obtiene todos los renglones con `api.obtener_articulos(codigo)`.
- Si ningún renglón es objetivo, guarda el proceso en
  `licitaciones_descartadas` con motivo
  "Sin artículos auditables en supermercado" y retorna False.
- Si hay renglones objetivo, llama a `evaluar_renglones`, guarda con
  `_guardar_agrupado` y retorna True.

3.6. `evaluar_renglones()` — evaluación de precios
Parámetros relevantes:
- `filtrar_objetivos=True` por defecto; en recálculos se pasa False.
- `monto_total_conocido` permite conservar el monto global original al
  recalcular.

Fases:
1. Intenta crear `GeminiMarketEvaluator`. Si no hay `GEMINI_API_KEY`, usa
   fallback local (oferta mínima) y avisa por consola.
2. Recorre los artículos objetivo y, para cada uno, consulta:
   `buscador.buscar_ofertas_cadenas_verificadas(descripcion_usuario, limite=10)`.
3. Agrupa los artículos con candidatos en bloques de 15.
4. Por cada bloque envía a Gemini un JSON con:
   `id_articulo`, `producto_dgcp`, `unidad_dgcp` y `candidatos_mercado`
   (id, producto_catalogo, establecimiento, precio, url).
5. Gemini devuelve por artículo: `id_oferta_elegida`,
   `factor_multiplicador` y `razonamiento`.
6. `GeminiMarketEvaluator` transforma el candidato elegido en
   `OfertaSupermercado` con `monto = precio_catalogo * factor`.
7. Si Gemini no devuelve resultado para un artículo, se usa
   `seleccionar_oferta_minima` sobre sus ofertas crudas.
8. Calcula por fila:
   - `diferencia = precio_unitario_estimado - precio_mercado`.
   - `porcentaje = diferencia / precio_mercado * 100` solo si diferencia > 0.
   - `ALTO_RIESGO` si porcentaje > 15; `ALERTA_AMARILLA` si porcentaje > 0;
     `PRECIO_JUSTO` en otro caso.
   - `total_mercado = precio_mercado * cantidad`.
9. Acumula `monto_total` (o usa `monto_total_conocido` si es > 0),
   `monto_evaluable`, `monto_mercado`.
10. Calcula `diferencia_global`, `sobreprecio_global` y estado global:
    "Justa" si `sobreprecio_global <= 15`, "Sobrevalorada" si hay filas y
    supera 15, "Irregular" si no hay filas evaluadas.
11. Devuelve `{version, renglones_sin_referencia}`.
12. Ante una excepción crítica devuelve una versión de respaldo con estado
    "Error" y `auditoria_renglones` vacío.

Fórmulas críticas del motor DGCP:
```text
diferencia          = precio_licitado_unitario - precio_mercado_unitario
sobreprecio_%       = (diferencia / precio_mercado_unitario) * 100   si diferencia > 0
total_mercado       = precio_mercado_unitario * cantidad
monto_evaluable     = suma(precio_total_estimado de renglones evaluables)
monto_mercado       = suma(total_mercado de renglones evaluables)
diferencia_global   = monto_evaluable - monto_mercado
sobreprecio_global% = (diferencia_global / monto_mercado) * 100      si diferencia_global > 0
monto_no_evaluable  = monto_total - monto_evaluable
```
Nota: este motor usa >0 % como alerta amarilla. No aplica la banda de
tolerancia del 1 % que sí existe en `domain/value_objects/umbrales_evaluacion.py`.

3.7. Rate limit y manejo de errores de Gemini
Archivo: `infrastructure/gemini_market_evaluator.py`.
- Modelo: `gemini-3.6-flash`.
- `response_mime_type="application/json"`, `temperature=0.0`.
- Lotes de 15 artículos (`TAMANO_BLOQUE = 15`).
- Después de cada bloque se ejecuta `time.sleep(60)`, incluso después del
  último bloque. No hay token bucket ni control de RPM aparte de esta pausa.
- Reintentos: máximo 3 (`max_reintentos=3`).
- Solo reintenta errores `APIError` con código 429 o 503, esperando 15 s.
- Otros errores de API o excepciones inesperadas devuelven `{}` y el flujo
  continúa con fallback local.
- El prompt instruye identidad de producto, proporción lógica, corrección de
  errores de digitación y factor de empaque.
- La respuesta se valida contra los candidatos originales por índice; un
  `id_oferta_elegida` inválido o nulo se ignora.

3.8. Scraping de supermercados
Archivo principal: `infrastructure/market_search_adapter.py`.

`CatalogoDirectoSupermercados` consulta catálogos públicos sin API de pago:
- Nacional: Magento HTML `https://supermercadosnacional.com/catalogsearch/result/`.
- Jumbo: Magento HTML `https://jumbo.com.do/catalogsearch/result/`.
- La Sirena: API VTEX `https://nuevo.sirena.do/api/catalog_system/pub/products/search`.
- Plaza Lama: buscador web `https://plazalama.com.do/search?name={consulta}`.

Comportamiento:
- Rate limit por host: mínimo 0.25 s entre solicitudes (`_solicitar`).
- Caché en memoria de 300 s por (cadena, consulta).
- Normaliza tildes, mayúsculas, fracciones, unidades de masa/volumen y empaques
  (`CAJA/48`, `FARDO DE 24`, `SIX PACK`, etc.).
- Aplica filtro negativo semántico para evitar falsos positivos (carnes,
  snacks, bebidas, adobos, etc.).
- Escenarios de comparación:
  A/B: ajusta precio por proporción de tamaño/peso/volumen y empaques.
  C: convierte precio por libra a precio por unidad agrícola usando peso
  aproximado o pesos promedio (sandía 10 lb, melón 5 lb, piña 2 lb, auyama 5 lb,
  repollo 4 lb).
- `_evaluar_presentacion` devuelve precio normalizado y explicación de
  equivalencia.
- `buscar_para_renglon` busca en las cuatro cadenas, normaliza cada oferta y
  conserva la más barata por cadena; luego ordena por monto.
- `buscar_ofertas_cadenas_verificadas` es un wrapper compatible que usa
  `buscar_para_renglon` con `unidad_medida="Unidad"`.

`SerpApiBuscadorSupermercados` existe como implementación legacy basada en
SerpApi/Google Shopping, pero el sincronizador usa el catálogo directo.

`dgcp_scraper.py` contiene:
- `DgcpScraper`: scraper HTML genérico con selectores CSS configurables. No es
  el usado por `dgcp_sync.py`; se conserva para pruebas/otros portales.
- `DgcpOpenDataClient`: cliente real de la API DGCP. Pagina `/procesos` y
  `/procesos/articulos`, usa `page`, `limit` (100 por defecto, máximo 1000),
  timeout 20 s y detecta `hasError`/`payload.content`.

Detalles de versionado en `_guardar_agrupado`:
- Lee el documento existente.
- Conserva las versiones previas, elimina la que tenga el mismo `id_version`
  y agrega la nueva.
- Como `id_version` es siempre `auto-{codigo}`, una nueva sincronización del
  mismo proceso reemplaza la versión automática existente en lugar de acumular.
- `version_original` se conserva si ya era un mapa con un `id_version`
  distinto; si no, se asigna la versión actual.
- `renglones_sin_referencia` guarda los artículos objetivo para los que no se
  encontró precio de supermercado.

4.2. Colección `licitaciones_descartadas` (nueva)
ID del documento: `codigo_proceso`.
Propósito: caché negativa permanente para evitar reprocesar cada 2 horas
procesos que no pertenecen al rubro o que no tienen artículos auditables.

Esquema:
```text
licitaciones_descartadas/{codigo_proceso}
{
  codigo: string,
  motivo: "No cumple filtro de rubro"
        | "Sin artículos auditables en supermercado"
}
```
Características:
- No guarda timestamp.
- No se elimina automáticamente; si un proceso descartado debe reevaluarse,
  hay que borrar su documento manualmente.
- `_procesos_nuevos` verifica que el código no exista ni en `licitaciones` ni
  en `licitaciones_descartadas`.

4.3. Otras colecciones (modelo de dominio)
- `productos`: id, nombre, nombre_normalizado, categoria, unidad_medida,
  marca, descripcion, activo.
- `precios_mercado`: id, producto_id, precio {monto, moneda}, fuente,
  fecha_registro, vigente.
- `precios_reportados`: id, producto_id, precio {monto, moneda},
  establecimiento, fecha_reporte, distrito, reportado_por.
- `evaluaciones`: id, producto_id, precio_reportado_id, precio_mercado_id,
  resultado, evaluado_en, version_regla, observacion.
Los importes se guardan como texto decimal, no float. Las fechas sin hora se
guardan como ISO `YYYY-MM-DD`; los datetime como timestamp nativo.

4.4. Recálculo de documentos existentes
`recalcular_documento`:
- Reconstruye artículos desde `auditoria_renglones` (producto, unidad, cantidad,
  precio licitado, precio total).
- Llama a `evaluar_renglones` con `filtrar_objetivos=False` y conserva el
  `monto_total` original si está disponible.
- Fusiona solo campos calculados: montos, diferencia, sobreprecio, estado,
  conteos, alerta, auditoría y motor_version.
- Conserva metadatos del proceso y alias.
- Añade `recalculado_en`.
- `--dry-run` en `recalcular_existentes.py` evita escribir.

`_siguiente_pendiente` devuelve el primer documento de `licitaciones` cuyo
`motor_version` sea distinto al actual. El ciclo automático recalcula como
máximo uno por ejecución cuando no hay licitaciones nuevas válidas.

5. CÁLCULOS FINANCIEROS DEL FRONTEND
===============================================================================
Archivo completo actual: `frontend/src/lib/impactoFinanciero.ts`.

```typescript
import type { ArticuloAuditoria, Licitacion } from "../types";

export interface ImpactoFinanciero {
  montoTotal: number;
  montoNoEvaluable: number;
  montoEvaluable: number;
  porcentajeMedible: number;
  montoMercado: number;
  excedenteBruto: number;
  sobrevalorado: number;
  irregular: number;
}

function totalExcedente(articulos: ArticuloAuditoria[], estado: ArticuloAuditoria["estado"]): number {
  return (Array.isArray(articulos) ? articulos : []).filter(Boolean)
    .filter((articulo) => articulo.estado === estado && Number(articulo.diferencia) > 0)
    .reduce((total, articulo) => total + Number(articulo.diferencia) * articulo.cantidad, 0);
}

export function calcularImpactoFinanciero(licitacion: Licitacion): ImpactoFinanciero {
  const articulos = Array.isArray(licitacion?.auditoria_renglones) ? licitacion.auditoria_renglones : [];
  const sobrevalorado = totalExcedente(articulos, "ALTO_RIESGO");
  const irregular = totalExcedente(articulos, "ALERTA_AMARILLA");
  const excedenteBruto = sobrevalorado + irregular;
  const montoTotal = Number(licitacion?.monto_total) || 0;
  const montoNoEvaluable = Number(licitacion.monto_no_evaluable ?? "0");
  const montoEvaluable = montoTotal - montoNoEvaluable;

  return {
    montoTotal,
    montoNoEvaluable,
    montoEvaluable,
    porcentajeMedible: montoTotal > 0 ? montoEvaluable / montoTotal * 100 : 0,
    montoMercado: Number(licitacion?.monto_mercado) || 0,
    excedenteBruto,
    sobrevalorado,
    irregular,
  };
}

export function formatearRD(value: number): string {
  return `RD$ ${value.toLocaleString("es-DO", { minimumFractionDigits: 2, maximumFractionDigits: 2 })}`;
}
```

Fórmulas efectivas:
```text
montoEvaluable     = monto_total - monto_no_evaluable
porcentajeMedible  = montoEvaluable / monto_total * 100
excedentePorEstado = Σ (diferencia * cantidad) para filas del estado
                     donde diferencia > 0
excedenteBruto     = sobrevalorado + irregular
```
Importante: el frontend solo suma diferencias positivas por renglón; no
compensa renglones con diferencia negativa. Por eso `excedenteBruto` puede no
coincidir exactamente con `diferencia_global` del backend, que usa
`montoEvaluable - montoMercado`.

6.1. Capa de datos

Backend relevante:
- `GET /licitaciones` fusiona las versiones estáticas DASAC con los documentos

  devuelve una lista plana de versiones.
- Si Firestore falla, devuelve solo el caso DASAC estático.
- Los endpoints de lectura usan caché en memoria de 5 minutos con
  stale-while-revalidate; `force_refresh` real se acepta como máximo una vez
  cada 60 s globalmente.

6.2. Dashboard principal (`src/App.tsx`)
Estado:
- `datos: DashboardData | null`
- `cargando`, `error`
- `filtro: FiltroRiesgo`
- `busqueda: string`
- `detalle: boolean`
- `versionActiva: string`

Flujo:
1. Al montar, llama `obtenerDashboard` con `AbortController`.
2. Normaliza defensivamente cada licitación con `normalizarLicitacion`:
   tolera campos legacy (`codigo_proceso`, `renglones`, `productos`,
   `nivel_riesgo`, etc.), convierte números y strings, y garantiza estados
   válidos.
3. Agrupa por `codigo` con `agruparLicitaciones`; `original` es la versión de
   menor número y `versiones` queda ordenado.
4. La búsqueda principal filtra grupos por código, título o fecha.
5. `licitacion` activa se busca por `id_version`; si no existe, usa el original
   del primer grupo.
6. Calcula conteos por estado y un `ResumenRiesgo` local.
7. La "última actualización" se deriva del máximo `evaluado_en` de las
   evaluaciones.

9. OBSERVACIONES PARA EL PRÓXIMO LLM
===============================================================================
1. Hay dos fuentes de licitaciones: Firestore y el caso DASAC estático en
   `presentation/routers/licitaciones.py`. No eliminar la fusión sin migrar el
   caso estático.
2. El motor DGCP clasifica cualquier sobreprecio positivo como
   `ALERTA_AMARILLA`; el dominio clásico usa una banda de tolerancia del 1 %.
   No unificar ambos comportamientos sin decisión explícita.
3. `licitaciones_descartadas` es una caché negativa permanente sin timestamp.
   Para reintentar un proceso hay que borrar su documento.
4. `_guardar_agrupado` usa `set()` completo: sobrescribe el documento. Si se
   añaden campos nuevos, deben incluirse en esa escritura para no perderlos.
5. `id_version` automático es siempre `auto-{codigo}`; por eso una nueva corrida
   reemplaza la versión automática previa. El versionado histórico real solo
   ocurre si cambia el `id_version`.
6. `monto_no_evaluable` puede faltar en documentos antiguos; el frontend lo
   trata como 0.
7. `excedenteBruto` del frontend suma solo diferencias positivas por renglón;
   `diferencia_global` del backend usa `montoEvaluable - montoMercado`. Pueden
   discrepar; no asumir equivalencia exacta.
8. El estado de respaldo del backend es "Error" si falla la evaluación, pero el
   tipo `Licitacion` solo admite "Justa" | "Irregular" | "Sobrevalorada"; el
   normalizador del frontend convierte cualquier otro valor en "Irregular".
9. `DGCP_MAX_PROCESSES` aparece como 50 en el código y 3 en el README; Render
   lo fija en 1. Verificar antes de cambiar la documentación.
10. `TarjetaProducto`, `TablaComparacion` y `construirComparaciones` son legado
    no usado por el dashboard actual.
11. El prompt de Gemini y el modelo `gemini-3.6-flash` están hardcodeados en
    `gemini_market_evaluator.py`; el rate limit depende de pausas fijas, no de
    cuotas dinámicas.
12. El frontend compilado se sirve desde el mismo proceso FastAPI en producción;
    `VITE_API_URL` vacío es el comportamiento esperado en ese despliegue.
